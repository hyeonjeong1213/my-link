# 마이링크 (MyLink) 상세 사용자 시나리오

본 문서는 마이링크 서비스의 다양한 사용자 행동 스펙과 예외 상황을 고려하여, **방문자(Visitor)**와 **소유자(Owner)**의 관점에서 가능한 모든 시나리오를 "사용자는 \_\_하기 위해 \_\_한다" 형식으로 정의한 공식 시나리오 명세서입니다.

---

## 1. 방문자 (Visitor): 마이링크 페이지 방문 과정

### 1.1 랜딩 및 프로필 페이지 조회
* **시나리오 1 (서비스 탐색 및 랜딩)**
  * 사용자는 **서비스의 개요를 파악하고 가입 여부를 결정하기 위해**, 루트 경로(`http://localhost:5173/`)에 첫 접속하여 미니멀리즘 다크 모드 소개 카드와 "Google 계정으로 시작하기" 버튼을 확인한다.
* **시나리오 2 (소유자 프로필 조회 진입)**
  * 사용자는 **소셜 미디어 프로필을 통해 연결된 특정 소유자의 퍼블릭 링크들을 조회하기 위해**, 소유자의 고유 주소(`http://localhost:5173/{displayName}`) 경로로 직접 브라우저에 입력하거나 공유된 링크를 탭하여 접속한다.
* **시나리오 3 (잘못된 경로 진입 처리)**
  * 사용자는 **존재하지 않는 사용자나 잘못된 경로로 접근하여 당황하지 않고 올바른 시작점으로 돌아가기 위해**, 화면에 표시되는 "존재하지 않는 마이링크 페이지입니다" 안내 문구와 함께 메인 홈 화면으로 이동 가능한 "마이링크 시작하기" 링크 버튼을 확인한다.

### 1.2 미니멀 프로필 및 링크 인지 UX
* **시나리오 4 (프로필 정체성 확인)**
  * 사용자는 **이 페이지를 운영하는 소유자가 누구인지 명확히 인지하기 위해**, 글래스모피즘 카드의 최상단에 렌더링된 소유자의 아이디(`displayName`), 실제 본명(`username`), 그리고 정성스럽게 작성된 한 줄 소개글(`introduction`)을 차례로 읽는다. (단, 방문자 모드에서는 인라인 편집 연필 아이콘이 노출되지 않는 깔끔한 화면을 본다)
* **시나리오 5 (채널 구분 및 파비콘 인지)**
  * 사용자는 **소유자가 등록한 다채로운 소셜/웹 채널 목록을 시각적으로 쉽고 신속히 구별하기 위해**, Google Favicons API로부터 실시간으로 로드되어 링크 카드 좌측에 단정히 정렬된 각 외부 사이트의 오리지널 브랜드 로고(파비콘) 아이콘들을 확인한다.
* **시나리오 6 (로딩 과정의 안정성 확보)**
  * 사용자는 **네트워크 속도가 느릴 때 페이지 레이아웃이 튀거나 깜빡이는 시각적 소음을 겪지 않기 위해**, 파비콘 이미지 및 소유자 텍스트가 완전히 렌더링될 때까지 은은하게 펄스(Pulse) 애니메이션이 돌아가는 반투명 스켈레톤(Skeleton) 로딩 UI를 마주한다.

### 1.3 링크 클릭 및 이동 (클릭 카운팅)
* **시나리오 7 (외부 채널 연결 및 클릭수 증가)**
  * 사용자는 **소유자의 실제 작업 공간(예: GitHub, 개인 블로그, 포트폴리오 등)으로 빠르게 이동하기 위해**, 목록 중 원하는 채널의 링크 카드를 클릭하여 새 탭(`target="_blank"`)으로 목적지 페이지를 띄움과 동시에, 해당 링크의 누적 클릭 수가 즉시 1회 무결하게 증가하도록 백그라운드에서 카운팅 API(Firestore increment)를 호출하게 한다.

### 1.4 디바이스 최적화 환경
* **시나리오 8 (모바일 기기 뷰잉 최적화)**
  * 사용자는 **인스타그램, X(트위터) 등 주요 소셜 미디어 앱 내부에서 기본 제공하는 인앱 웹뷰(In-App Webview)나 다양한 모바일 해상도에서 화면 깨짐 없이 쾌적하게 조회하기 위해**, 디바이스 너비에 맞추어 레이아웃 패딩과 글씨 크기, 카드 폭이 우아하게 반응형으로 조절되는 모바일 퍼스트(Mobile-First) 디자인 인터페이스를 감상한다.

## 2. 소유자 (Owner): 링크 추가/수정/삭제 과정

### 2.1 계정 가입 및 초기 설정
* **시나리오 1 (구글 소셜 간편 가입)**
  * 사용자는 **이메일 입력 등 번거롭고 복잡한 절차 없이 본인의 프로필 공간을 생성하기 위해**, 메인 화면에서 구글 소셜 로그인 버튼을 클릭하여 쉽고 빠르고 안전한 인증 과정을 진행한다.
* **시나리오 2 (로그인 후 자동 프로필 초기 설정)**
  * 사용자는 **가입 직후 프로필 정보를 수동으로 전부 쳐야 하는 번거로움을 겪지 않기 위해**, 구글 인증 결과로부터 지메일 ID의 `@` 앞자리 텍스트(예: `hyeonjeong1213`)를 파싱하여 고유 URL Slug인 `displayName`으로 자동 매핑하고, 구글 실명(예: `황현정`)을 실제 `username` 필드로 지정한 후 바로 개인 관리 대시보드(`/`) 화면으로 자동 전환된다.

### 2.2 대시보드 관리 및 화면 전환 기능
* **시나리오 3 (내 마이링크 주소 신속 복사)**
  * 사용자는 **친구들이나 소셜 미디어 인스타그램/트위터 프로필 소개란에 본인의 링크 주소를 즉시 가져다 붙여넣기 위해**, 대시보드 상단 우측에 있는 "내 페이지 링크 복사" 버튼을 탭하여 주소를 클립보드에 담고, 화면 하단에 은은하게 뜨는 복사 성공 피드백 토스트 알림을 확인한다.
* **시나리오 4 (내 퍼블릭 완성 페이지 신속 확인 및 이동)**
  * 사용자는 **자신이 인라인으로 예쁘게 편집한 프로필 화면이 실제 외부인들에게 어떻게 보이는지 신속하게 확인하기 위해**, 대시보드 화면 우측 상단 고정 영역에 항상 노출되는 **"내 페이지 보기"** 버튼을 클릭하여 새 브라우저 창(`target="_blank"`)에서 본인의 완성된 퍼블릭 페이지를 로드한다.

### 2.3 프로필 인라인 편집 (Inline Edit)
* **시나리오 5 (displayName 변경 및 연필 아이콘 인지)**
  * 사용자는 **자신만의 커스텀 URL 주소 및 대표 표기 아이디가 언제든 편집 가능하다는 것을 직관적으로 인지하기 위해**, 대시보드 프로필 텍스트 우측에 항상 노출되는 **연필 아이콘(✏️)**을 눈으로 확인하고 해당 영역을 클릭하여 어두운 입력 창(`input`)을 활성화한 후 닉네임을 변경한다.
* **시나리오 6 (displayName 실시간 중복 검증 및 충돌 방지)**
  * 사용자는 **본인이 바꾼 URL Slug 주소가 시스템 내부의 다른 가입자와 충돌하여 오류가 나지 않도록 하기 위해**, 수정을 마치는 순간(Enter 혹은 Blur) Firestore에 실시간 쿼리하여 해당 문자열을 선점한 유저가 있는지 중복 여부를 자동으로 체크받고, 사용 가능할 시 정상 적용되며 이미 누군가 쓰고 있다면 붉은 경고 메시지와 함께 기존 명칭으로 안전하게 복귀됨을 확인한다.
* **시나리오 7 (실명 username 인라인 편집과 연필 표시)**
  * 사용자는 **방문자들에게 신뢰감을 주기 위해 실제 자신의 이름이나 현재 본인의 직책 명칭을 언제든지 마이페이지에서 바로 수정할 수 있음을 인지하기 위해**, `username` 우측에 항시 표시되는 **연필 아이콘(✏️)** 영역을 눌러 인라인 입력 창으로 진입한 후 값을 변경하고, 입력 영역 바깥을 눌러 실시간 저장한다.
* **시나리오 8 (한 줄 소개 introduction 인라인 편집과 연필 표시)**
  * 사용자는 **방문자들에게 건넬 매력적인 한 줄 소개글을 작성 및 편집할 수 있는 구역을 확실히 구분하기 위해**, `introduction` 영역 옆에 상시 노출된 **연필 아이콘(✏️)**을 인지하고 클릭하여 인라인 텍스트에어리어(`textarea`)를 열고 문장을 작성한 후 저장한다.

### 2.4 링크 카드 추가 / 수정 / 스키마 보정
* **시나리오 9 (새 외부 링크 채널 추가)**
  * 사용자는 **소개하고 싶은 새로운 개인 공간 주소를 링크 목록에 추가하기 위해**, 대시보드 링크 관리 구역 하단에 위치한 "+ 새 링크 추가" 버튼을 클릭하여 자연스러운 페이드인(Fade-in) 모션과 함께 기본 데이터 명칭(`새 링크`, `https://`)을 가진 신규 외부 링크 카드를 생성한다.
* **시나리오 10 (링크 타이틀 인라인 편집과 연필 표시)**
  * 사용자는 **링크 카드의 타이틀 텍스트를 마이페이지 대시보드 내부에서 바로 클릭하여 수정할 수 있음을 한눈에 알기 위해**, 링크 제목 옆에 항시 달린 **연필 아이콘(✏️)** 영역을 탭하여 제목 입력 창으로 진입하고 `내 공식 포트폴리오 웹사이트` 등으로 수정한다.
* **시나리오 11 (외부 링크 URL 주소 인라인 편집과 연필 표시)**
  * 사용자는 **연결 경로가 올바르지 않을 때 대시보드 내에서 간편하게 목적지 도메인을 변경할 수 있음을 알기 위해**, 주소 텍스트 필드 우측에 표시된 **연필 아이콘(✏️)** 영역을 탭하여 입력란을 띄우고 URL 경로를 수정하여 저장한다.
* **시나리오 12 (URL 스키마 자동 보정 및 실시간 파비콘 로드)**
  * 사용자는 **주소를 입력할 때 `https://` 등의 프로토콜을 생략하고 작성하더라도 연결 링크가 정상적으로 작동하도록 돕기 위해**, `github.com/hyeonjeong1213` 형식만 입력해두더라도 시스템 내부 정규식 엔진이 자동으로 `https://github.com/hyeonjeong1213` 형태로 결함을 메워주고, 변경과 동시에 추출한 도메인을 활용해 구글 API가 실시간으로 고화질 파비콘 아이콘을 매치하여 카드를 완성하는 시각적 즐거움을 맛본다.

### 2.5 링크 클릭 피드백 모니터링
* **시나리오 13 (링크별 누적 클릭수 카운트 확인)**
  * 사용자는 **본인이 올린 여러 채널 중에서 방문자들이 어떤 카드를 가장 흥미롭게 생각하고 자주 클릭했는지 성과를 파악하기 위해**, 각 링크 카드의 하단에 실시간으로 집계되어 노출되는 `👁️ 클릭수: {clicks}` 지표 수치를 확인하고 분석한다.

### 2.6 링크 카드 삭제
* **시나리오 14 (모달 방해 없는 즉각적 링크 삭제)**
  * 사용자는 **더 이상 쓰지 않거나 효력을 잃은 외부 링크 카드를 깔끔하게 정리하기 위해**, 링크 카드 우측 가장자리에 위치한 미니멀 쓰레기통 버튼을 클릭하여 별도의 흐름을 끊는 모달이나 체크 박스 팝업을 거치지 않고, 카드가 서서히 투명해지며 사라지는 페이드아웃 애니메이션과 함께 Firestore에서 링크 도큐먼트를 영구히 삭제한다.

### 2.7 세션 관리
* **시나리오 15 (로그아웃 세션 해제)**
  * 사용자는 **공용 디바이스나 타인의 기기에서 본인의 대시보드 제어 권한을 안전하게 회수하기 위해**, 대시보드 상단 구석의 로그아웃 버튼을 클릭하여 저장소 세션을 초기화하고 메인 인트로 화면으로 정상 리다이렉트 시킨다.
