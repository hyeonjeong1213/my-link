# 마이링크 (MyLink) 제품 요구사항 정의서 (PRD)

## 1. 프로젝트 개요
- **프로젝트명**: 마이링크 (MyLink)
- **목적**: 텍스트 위주의 매우 심플하고 미니멀한 형태로 다양한 채널 주소를 하나의 URL로 모아 사람들과 공유할 수 있는 서비스 제공.

---

## 2. 핵심 기능 목록 (MVP)

### 2.1 사용자 인증 (Firebase)
- 파이어베이스(Firebase) Authentication을 활용한 구글(Google) 소셜 로그인 기능 단독 제공.

### 2.2 사용자 URL 및 닉네임 정책
- 가입 후 별도의 영문 핸들(Handle)이나 아이디를 설정하지 않음.
- 유저의 **닉네임(nickname)**을 퍼블릭 라우팅 주소로 그대로 사용하여 `도메인.com/닉네임` 형태로 웹 페이지 링크 노출.

### 2.3 텍스트 기반 프로필 (인라인 편집)
- **이미지 업로드 기능은 일체 제공하지 않음**.
- 사용자의 닉네임과 짧은 자기소개글은 모두 대시보드 화면상에서 텍스트를 클릭해 곧바로 수정하는 **인라인 편집(Inline Edit)** 방식으로 동작 및 저장.

### 2.4 링크 관리 (인라인 편집 및 파비콘 API 연동)
- 새로운 텍스트 링크 추가 기능.
- 개별 링크의 '제목(Title)'과 '주소(URL)' 역시 별도 수정 페이지나 모달이 아닌, 대시보드에서 텍스트를 탭하여 바로 고치는 **인라인 편집** 방식 적용.
- 링크 삭제 기능.
- **파비콘(Favicon) 연동**: 사용자가 직접 이미지를 업로드할 필요 없이, 목적지 URL 문자열을 기반으로 **구글 파비콘 API**를 활용해 아이콘을 동적으로 가져와 렌더링.
- *(향후 계획: 특정 링크에 대한 클릭 조회수 카운팅 기능 추가)*

### 2.5 퍼블릭 프로필
- 닉네임과 한 줄 소개, 그리고 파비콘이 달린 텍스트 링크 목록만 노출되는 극도의 미니멀리즘 페이지 (선택 가능한 테마 기능 없음).
- 전면 UI 구성은 **shadcn/ui** 컴포넌트로 깔끔하게 통일.

## 3. 데이터베이스 모델링 (Firestore)

빠른 조회와 독립된 구조 관리를 위해 파이어베이스 Firestore내에서 `users` 최상위 컬렉션 하위에 `links` 서브 컬렉션(Sub-Collection)을 배치합니다.

### 3.1 Collection: `users`
사용자의 기본 정보를 담는 엔티티. Firebase Auth 연동 즉시 생성.
- **Document ID**: `{uid}` (Firebase 사용자 고유 식별값)
- **Fields**:
  - `nickname` (string): 퍼블릭 페이지 라우팅 기준이자 유저 식별 이름.
  - `introduction` (string): 프로필 화면에 노출될 짧은 소개글.

### 3.2 Sub-Collection: `links`
해당 유저(uid) 하위에 종속되어 실무 링크들을 저장하는 컬렉션. (`users/{uid}/links/{linkId}`)
- **Document ID**: `{linkId}` (Firestore Auto-Generated ID)
- **Fields**:
  - `title` (string): 화면에 보여질 텍스트 구조의 링크명.
  - `url` (string): 이동하게 될 목적지 웹 주소 포맷.
  - `createdAt` (timestamp): 링크 노출 순서를 정하기 위한 생성 일시.
  - *(※ 파비콘은 DB에 저장하지 않으며 프론트 단에서 `https://s2.googleusercontent.com/s2/favicons?domain={url}` 형태로 실시간 노출 처리함)*
